# Data and output dictionary

All paths below are relative to the repository root. Files under `data/evidence/` are supplied inputs and reference records. The entry point writes new calculations only under `generated/`.

## Source inputs

| Path | Contents and units |
|---|---|
| `data/evidence/05_reconstruction/data/*_metadata.csv` | One row per expression profile; `sample_id` joins all feature files. Metadata identify compound, cell, condition, source tier and binary outcome label. |
| `data/evidence/05_reconstruction/data/*_embeddings.csv` | `sample_id` plus `emb_0` through `emb_767`; one 768-dimensional embedding per profile. |
| `data/evidence/05_reconstruction/data/*_pathways.csv` | `sample_id` plus 54 pathway values. Pathway names/order are defined in `assets/pathways_54.gmt`. |
| `data/evidence/05_reconstruction/assets/` | Pathway definitions and upstream feature-generation configuration. |
| `data/evidence/05_reconstruction/results/expression_inputs.json` | Expression-collection counts and original input checksums. |
| `data/evidence/07_reference_study/data/lung.csv` | Public lung-cancer patient snapshot. `status`: 0 censored, 1 death; `time`: days; `age`: years; `sex`: original numeric coding; `ph.ecog`: numeric ECOG. |
| `data/evidence/07_reference_study/data/lung.source.json` | Clinical source URL and input identity. |

The MHEDILI collection contains 7,818 profiles and DILImap contains 763. `reconstructed_features.load()` selects the source and PHH cohorts, normalizes compound aliases, identifies controls and excludes source-overlapping compounds from external evaluation. `config.json` records every evaluation sample identifier. The resulting panel sizes are 20 compounds / 1,458 profiles for the within-source holdout, 49 / 583 for DILImap, and 11 / 227 for PHH.

These scripts start from the supplied feature matrices. Raw expression collections and upstream model weights are identified by the source and configuration records. They are not needed to run the downstream calculations described here.

## Application models and scores

Directory: `data/evidence/05_reconstruction/results/experiments/`.

| File or field | Meaning |
|---|---|
| `config.json` | Evaluation sample IDs, reference groups, ordered model definitions and permutation seed offsets. |
| `n60_seedN.json` | Training identifiers, coordinate assets, scales, objectives and draw-specific results. N ranges from 0 to 9. |
| `n60_seedN_state.npz` | Fitted kernel coefficients, coordinate weights, intercepts, raw Softplus parameters and training IDs. |
| `n60_seedN_PANEL_scores.npz` | Profile scores for `source`, `external` or `PHH`; all arrays follow the saved sample/compound order. |
| `full`, `linear`, `kernel` | Arrays with one row per profile and six model columns. The full score is `linear + kernel + b`, where `b` is the corresponding state-file intercept. Adding this constant to the retained score leaves all pair differences unchanged. |
| `arm_names` | Names of the six model columns: full predictor and kernel-only model for each of three designs. |
| `diagnostic`, `diagnostic_names` | The unfitted two-coordinate sums for the three designs. |
| `compound`, `label` | Compound identifier and outcome label for each profile. |

Use array names rather than numeric column assumptions. `source` means within-source holdout and `external` means DILImap. `historical_centred`, `matched_centred` and `revised_origin` mean pooled-centred, matched-centred and origin-preserving, respectively. `softplus_original` is the full predictor identifier; `kernel_original` is the separately fitted kernel-only reference score. `fixed_sum` is the fixed coordinate sum. In machine-readable records, `certificate` and `budget` denote the bound, `audit` denotes the component analysis, and `vulnerable` denotes pairs flagged by the inclusive screen.

`data/evidence/05_reconstruction/results/fit_validation/` contains the three small real-data fits used for the independent gradient validation in SI G.4. The 15 synthetic validation fits are regenerated by `check_small_fits.py` and cover five model families three times each. These are implementation checks.

## Frozen-reference sensitivity

`data/evidence/07_reference_study/assets/frozen_reference.json` stores the fixed coordinate prototypes and scales. `results/fits/` contains 31 state files and the PHH/DILImap scores for labelled training sizes 4, 20, 60 and 102. Each state has one full-model column. The 102-compound case uses seed 0. `caps` stores the compound-balanced hinge weights.

## Simulation records

| Directory | Structure |
|---|---|
| `data/evidence/07_reference_study/results/simulation/` | 14,400-row CSV, with n, strength, geometry, retained distribution, replicate number, seed and pairwise statistics. |
| `data/evidence/04_results/extension_double/` | 200 fitted-simulation NPZ files. Score arrays have axes displacement (3), evaluation observation (300), fitted model (4). Model order is informative/positive start, informative/zero start, noise/positive start, noise/zero start. |
| `data/evidence/08_inference/` | 80 `case_NN.npz` files. `estimate` and `se` have 2,000 rows and three columns ordered Delta, A, B. Bootstrap limits use the same ordering. The design JSON lists scenario IDs and seeds. |
| `data/evidence/08_permutation/` | Permutation settings and all 60,000 drops for three designs, two panels and ten draws. |
| `data/evidence/06_methods/` | Scalar and weighted-pair checks, limiting calculations, rank enumeration, bound curves and the corresponding reference records. |
| `b_robustness/` | Folded-perturbation parameters, scripts, compound score records and numerical results for SI H.5. |

## Generated results

`generated/key_results.csv` identifies 87 reported quantities, their locations and exact JSON paths. `generated/tables/` contains numeric table rows and LaTeX table blocks. `generated/figures/` contains vector PDF and PNG outputs. `generated/verification.json` records the comparisons with the published numerical targets; `generated/plot_verification.json` records the font and plotting inputs. Complete subprocess output is in `generated/logs/`.

`generated/inference_verification.json` distinguishes reaggregation of all saved datasets from newly generated subset checks. `generated/state_replay.json` reports parameter-to-score replay. Fresh full refits and all-dataset regeneration are optional commands in `REPRODUCTION.md` and write to separate output directories.
